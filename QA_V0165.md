# Beatronome v0.16.5 — UI overlap and regression audit

## Changes
- **Music Knowledge header:** the favorite (☆/★) button and expand/collapse (+/−) button now share an in-flow action group. The old absolutely positioned favorite caused them to overlap.
- Favorite remains accessible and usable while the card is collapsed. Buttons expose `aria-pressed` and `aria-expanded` plus descriptive labels.
- Small screen text wrapping and button sizing were adjusted without modifying the underlying music content or calculator logic.
- **Additional issue found and corrected:** in the 701–1099 px tablet/small-PC layout, the tuner strings card spanned both columns while the tuner display still occupied the same row. The tuner now explicitly places controls + display on one row and strings on the next row, without overlap.
- PWA shell version and newly added `fix-v0165.css` precache entry were updated to v0.16.5.

## Verification performed
- Chromium layout smoke tests with 320, 360, 390, 430, 768, 1024 and 1440 px simulated viewports. These tests use inline-loaded app assets because the environment blocks navigation to a local web server. This is still a browser-rendering test, but it does **not** validate real-origin Service Worker behavior.
- All three Jazz reference cards contained **two distinct header actions** with zero button intersections at every tested width.
- Clicking the favorite updated its `aria-pressed` state; clicking expand updated `aria-expanded` at every width.
- Main Metronome, Groove, Tuner, Practice and More screens were screened for visible input/button overlap and horizontal overflow. No horizontal overflow was detected in the Knowledge screen; no JS page errors were raised.
- A separate 1024 px tuner layout check verified that the tuner display ends above the strings card (non-overlapping layout).
- Existing fixed footer navigation can intersect scrolling content in geometric screenshots; this is normal for a fixed bottom bar and not evidence of a control-to-control overlap. The final screen's extra bottom padding remains intact.
- Node syntax checks for application JavaScript, static asset reference verification, sample count and ZIP integrity checks passed.

## Not verified here
- Real iOS Safari / Samsung Internet and device-specific touch behavior, microphone permission, actual audio fidelity/latency, Bluetooth output, YouTube API playback and Supabase end-to-end synchronization.
- Service Worker upgrade path on GitHub Pages. Confirm version v0.16.5 after closing all active instances and reopening.
