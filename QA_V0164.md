# Beatronome v0.16.4 — Validation

## Source basis
- Updated the exact `Beatronome_v0.16.3_Responsive_Layout_Fix.zip` as provided in this conversation.
- Existing backing-track localStorage key `beatronome-backing-v1` is unchanged.

## Changes
- Both local-file and YouTube LOOP cards show `LOOP / START / END / LOOP ON|OFF / CLEAR`.
- YouTube Speed control is a 25–200% range slider, step 5%; editable percentage and ±5% buttons.
- Requests are sent through the official `YT.Player.setPlaybackRate()` and actual playback is read back with `getPlaybackRate()` / `onPlaybackRateChange`.
- If YouTube does not support a 5% increment, the UI shows the requested and **actual** speed separately, instead of suggesting that unsupported playback rates worked.

## Validation
- Node syntax checks for all shipped JS, and CSS parser validation.
- HTML duplicate-ID and referenced-script/assets checks.
- Mocked official-player functional tests: 25%, 95% (requested vs applied), 175%, numeric step normalization and persistence.
- Service Worker shell cache and version consistency.
- ZIP file integrity.

## Limitations
- The environment's Chromium is blocked from local navigation (`ERR_BLOCKED_BY_ADMINISTRATOR`), so visual responsive checks in real desktop/mobile browsers could not be completed here.
- Live playback against YouTube's actual servers was not performed. Playback rates depend on the video's `getAvailablePlaybackRates()` and are not guaranteed to follow 5% increments, even when the YouTube website offers granular controls.
