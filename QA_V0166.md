# Beatronome v0.16.6 — Fix & QA report

## Reported bugs and implementation
1. **Music Knowledge — Recent / Favorites chips appeared white.** The existing `.knowledge-chip-row button` CSS set borders and text color but did **not** set a background color. Browser default button backgrounds could therefore render white. New last-loaded `fix-v0166.css` defines a dark background, high-contrast text, hover/focus states, and wrapping for narrow screens.
2. **Internal Clock stayed ON after its section was collapsed.** The old `trainingExpanded` variable was a transient UI flag; collapsing only hid HTML and never changed `training.internalEnabled`. The panel header itself was misleadingly named "Internal Clock", though it contained several training tools. Now the panel is named "고급 훈련". Collapsing that panel or hiding advanced features turns **Internal Clock** OFF immediately, saves OFF, and shows an acknowledgement. The sound/mute bar counts are preserved. Reopening does not silently turn it back ON.
3. **Persisted state edge cases.** `practice.trainingExpanded` is now persisted. Legacy saved state with active Internal Clock behind a hidden panel is normalized to OFF. Preset import, cloud merge, local backup import, reset, and app reload align the expanded UI state and the audio enable flag. Pending debounced BPM saves are flushed on page hide/visibility loss.
4. **Real-time updates and cloud in-flight edits.** The training switch updates state/visible feedback immediately, while subsequent Web Audio scheduling reads the updated state. Network sync uses an in-memory revision counter to avoid silently clearing local edits that occur while remote fetch/upload is in progress. It queues a follow-up sync only after a successful request if more unsent edits remain (no tight retry loop on a failed network request).
5. **Offline/update assets.** App/SW references and the precache manifest include the new CSS and use v0.16.6. No forced reload is introduced during an active audio session.

## Automated tests performed
- `node --check` on application, service worker and related JS.
- Source-level JavaScript regression tests (`node QA_V0166_TESTS.js`): 11 state/layout checks, one live scheduling invariant test (ON → mute bar → OFF → next bar audible without stop), and one **mock-network** cloud sync in-flight change test.
- Static duplicate-ID, CSS parsing, file linkage, version consistency and Basic WAV checks.

## Not verified (and should not be represented as verified)
- Physical iPhone Safari, Galaxy/Android Chrome, and Mac Safari UI interactions or screenshot/layout testing. In this execution environment Chromium navigation was blocked with `ERR_BLOCKED_BY_ADMINISTRATOR` for HTTP, file and data URLs.
- A real Supabase user login / two-device simultaneous sync; only isolated state and mocked network logic was tested.
- Physical audio timing, Bluetooth speaker latency, microphone tuning fidelity, or Service Worker install/update across real deployed versions.

## Suggested device smoke test after GitHub deployment
1. Open More → Music Knowledge and confirm recent-item chips have dark backgrounds and readable text.
2. Expand Advanced → Training → turn Internal Clock ON; collapse the Training header. Observe OFF and immediately saved state; reopen and verify still OFF.
3. Repeat with "고급 기능 접기" in Quick Settings. Relaunch the app: Internal Clock must remain OFF, previous sound/mute counts still present.
4. Start the metronome, turn Internal Clock ON and OFF while playing, confirm it never stops and subsequent clicks follow the current choice (scheduled lookahead may introduce a short audible delay).
5. Change BPM and subdivision, switch tabs, close/reopen, and verify the selected values and current audio behavior are consistent.
6. If signed in, test iPhone → Mac sync with separate presets and offline edits, then reconnect and verify no edits were lost.
